SPICA FRONTEND REDESIGN — PROPOSAL G

素PLAIN — 引き算のミニマリズム。整列と余白だけで作る

装飾を足すのではなく、引くことで作る案。色は 6 個、角丸は 1 種、影は 0 個、字は 6 段、余白は 4px の倍数だけ。 右のウィジェット列を既定で消し（タグやサーバー情報は専用ページへ）、タイムラインは罫線 1 本だけで区切ります。 美しさは装飾ではなく整列と余白の一貫性から出します。この案は「コードの正しさ」を設計に直結させるため、 トークン・部品・検査できる規則を「03 システム」に明記しています。

Palette（6 色で全部）

#FFFFFF #FAFAFA #EAEAEA #111315 #6B7078 #2563EB

Keywords

引き算余白整列 トークンだけ影ゼロ検査できる
色は 6 個。増やすときは置き換える

地・面・罫・字・副字・アクセント。注意色（朱）を足しても 7 個。色が少ないほど、アクセントが効く。

区切りは罫線 1 本だけ

カード・影・塗り分けを使わない。1px の罫と余白だけで区切ると、画面が軽くなり、目線が動かない。

逸脱は検査で防ぐ

トークン以外の色・px・影を書かない。`grep` と CI で機械的に検査できる規則として残す。

03システム（設計のすべて）

この 1 枚が実装の根拠になります。トークン → 部品 → 検査できる規則、の 3 段だけ。

トークンと規則

画面はこの下の「部品」だけで組み、部品はこのトークンだけで書きます。トークンに無い値を使った時点で設計違反です。

色（6 + 注意色 1）

--bg
--surface
--line
--text
--text-sub
--accent
--danger

余白（4px の倍数だけ）

4 8 12 16 24 32

字（6 段だけ）

--t-628 見出し
--t-520 画面名
--t-416 本文（大）
--t-314 本文
--t-213 副（時刻・件数）
--t-112 ラベル

部品（これだけで全画面を組む）

ノート フォロー キャンセル 下書き 検索 す み CW アンケート ★4✦2

構造（部品は 8 個。画面はその組み合わせ）

App ├─ Nav … 全画面で共通（消さない） └─ Screen ├─ ScreenHead … 画面名 + タブ + 件数 ├─ Feed … List │ └─ Post × n ← 通知・検索・プロフィールでも同じ │ ├─ Avatar / Meta │ ├─ Body / CW / Media / Quote / Poll │ ├─ Reactions │ └─ Actions └─ Aside … 任意（畳める）

検査できる規則（レビューと CI で機械的に守る）

  • トークン定義以外に色を書かない（#hex・rgb() の出現が 0 件）grep
  • !important を使わない（テーマはトークンの差し替えだけで作る）grep
  • 余白・寸法は --s-* 以外を使わない（4px の倍数）レビュー
  • 角丸は --radius の 1 種類だけ。影は使わないレビュー
  • アイコンのサイズは 16 / 20 の 2 種類だけレビュー
  • 遷移は 120ms / 180ms の 2 種類だけ（ease-out）レビュー
  • 部品は components/ の 8 個にだけ置く（画面側にスタイルを書かない）構造
