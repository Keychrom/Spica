## 1. 投稿とタイムライン

| 機能 | 説明 |
| :--- | :--- |
| **ノート作成** | 本文・CW（閲覧注意）・公開範囲・アンケート・引用・返信・メディア添付に対応。カスタム絵文字の入力補完つき。 |
| **リアクション** | 絵文字でリアクションできます。カスタム絵文字にも対応し、Misskey 等の連合先と相互送受信できます。 |
| **3段階の公開範囲** | 公開（連合配信）／ローカル限定／フォロワー限定。フォロワー限定は承認済みフォロワーの Inbox にだけ届き、リレーには配信しません。 |
| **リノート / 引用** | リノートと、引用元を保持した引用ノート。 |
| **タイムライン** | ホーム／ローカル／連合（リレー含む）／ハッシュタグ／リスト／アンテナ／チャンネル。ハッシュタグはタグページ（`/tags/<tag>`）として開けて、そのまま共有できます。 |
| **リスト** | ユーザーを束ねた専用タイムライン。公開範囲とミュートワードを尊重します。 |
| **アンテナ** | キーワード条件で連合を含むタイムラインから自動収集し、新着を通知します。 |
| **チャンネル** | 話題ごとの投稿先。チャンネル単位のフォローとタイムラインを持ちます。**作成者（と管理者）は名前・説明・バナー・テーマ色・カテゴリを後から編集でき、アーカイブもできます**（チャンネル画面の歯車ボタン）。 |
| **検索** | SQLite FTS5（trigram）による日本語全文検索。`from:user` / `before:2026-09-01` / `after:2026-01-01` / `has:media` / `-除外語` の演算子に対応。 |
| **リンクプレビュー（OGP）** | 本文に URL を書くと、OGP（タイトル・説明・画像・サイト名）を取得してカード表示します。取得結果はキャッシュされ、SSRF 対策とサイズ・時間制限つきで動作します。 |
| **検索索引の範囲（設定可能）** | 既定では**ローカル投稿のみ**を索引します（Mastodon / Misskey 相当）。管理画面から「ローカル＋フォロー中アクター＋自分宛の返信」「すべて」へ広げられます。リレー経由の投稿まで索引すると DB が大きく膨らむためです。 |
| **リモートブーストの保存範囲** | 既定では**フォロー中アクターのブーストだけ**保存します（リレー経由のフォロー外ブーストは DB の約 1/4 を占めるため）。「すべて保存」「保存しない」も選べます。 |
| **ブックマーク / ピン留め** | 投稿の保存と、プロフィール上部へのピン留め。 |
| **画像の説明（alt）** | 添付ごとに説明文（最大1500文字）を付けられます。投稿画面の「ALT」欄から入力し、連合先には ActivityPub の `name` として届きます（Mastodon / Misskey の代替テキスト欄に表示）。相手が付けた説明も同じように取り込んで表示します。 |
| **下書き / 予約投稿** | 下書きの保存と、日時を指定した自動投稿（ローカル・リモート両対応）。 |
| **ミュート / ブロック** | ユーザー単位のミュート・ブロック。ミュートワードは本文と CW を対象に、大文字小文字の区別・単語単位の指定ができます。 |
| **鍵アカウント** | フォロー承認制。`manuallyApprovesFollowers` として連合先にも伝わります。 |
| **リアルタイム更新** | Server-Sent Events（SSE）で新着ノート・リアクション・通知を即時配信。クライアントは見たいストリーム（ローカル／ホーム／連合／タグ／チャンネル）を接続時に申告し、サーバーは必要な人にだけ配ります。 |
| **ページネーション** | タイムライン・プロフィール・ブックマーク・通知・チャンネル・アンテナをカーソルで遡れます（`X-Next-Cursor` ヘッダ）。 |

## 2. メディアとドライブ

| 機能 | 説明 |
| :--- | :--- |
| **画像添付** | 最大4枚・15MBまで。アップロード時に**サーバー側でメタデータ（位置情報など）を除去し WebP へ変換**します（アニメGIFは保護）。 |
| **動画・音声の添付** | 動画（MP4/WebM/MOV）と音声（MP3/OGG/WAV/M4A）は1投稿1件・最大50MB（`MEDIA_MAX_BYTES` で変更可）。再エンコードはせず、ActivityPub では `Document` として届きます。 |
| **保存先の選択** | S3 / Cloudflare R2 互換ストレージ、またはサーバー内 `data/uploads`（ローカル）へ保存。 |
| **🗂️ ドライブ** | アップロードしたメディアを一覧し、使用量（件数・サイズ）と投稿での使用状況を確認できます。投稿に添付していないファイルも残り、**使用中でないファイルはドライブから削除**できます（使用中のファイルは投稿を消すまで保護）。`MEDIA_QUOTA_MB` で容量上限を設定でき、超過アップロードは 413 で拒否されます。 |
| **🖼️ 画像プロキシ** | リモートのアイコン・添付画像・本文内の画像を、相手サーバーから直接読まず**このノード経由**で配信します（Mastodon の `/proxy` と同じ考え方）。閲覧者の IP や User-Agent が相手サーバーに渡らず、相手が落ちていてもキャッシュから表示できます。署名付き URL のみ受け付けるため開放プロキシにはなりません。既定で有効、管理画面から ON/OFF・キャッシュ上限・保持日数を変更できます。 |
| **🎞️ 動画サムネイル（任意）** | ffmpeg がインストールされていれば、動画の先頭付近から 1 フレームを抜き出してサムネイル（WebP）を生成し、タイムラインでは静止画＋再生ボタンで表示します（動画の先読みが減り軽くなります）。ffprobe があれば再生時間と解像度も記録します。**未インストールでもアップロードは成功**し、サムネイルが付かないだけです。 |

## 3. 通知

| 機能 | 説明 |
| :--- | :--- |
| **通知の種類** | フォロー・返信・メンション・リアクション・リノート／ブースト・アンテナ・引っ越し（Move）。予約投稿の公開通知は自分の操作の控えとして常に届きます。 |
| **リアルタイム配信** | SSE でその場に届きます。 |
| **Web Push（PWA）** | ホーム画面に追加してネイティブアプリのように利用できます。ブラウザやアプリを閉じていても端末の通知欄に届きます。 |
| **🔔 種類別設定** | 設定画面から種類ごとに ON/OFF できます。切った種類は**アプリ内通知・プッシュ通知の両方**に届かず、切っている間に起きた分は生成されません（過去の通知も一覧・未読件数から除外）。 |
| **✉️ メール通知（SMTP 設定時のみ）** | メールアドレスを確認済みのユーザーが設定画面で ON にすると、通知をメールでも受け取れます（既定 OFF）。**種類別設定で切った種類はメールも届きません**。短時間に複数届いた通知は 1 通にまとめ、同じ人へ連続で送らないよう間隔（既定 5 分）を空けます。SMTP 未設定のサーバーでは設定項目ごと表示されません。 |
| **🚩 運営への通報通知** | 通報が届くと、admin / moderate 権限を持つ運営メンバー全員に `report` 種別の通知が届きます（通知をタップすると管理パネルの通報タブが開きます）。通報者自身には届きません。種類別設定で切ることもできます。 |
| **まとめ表示** | 同じ種類・同じ投稿への通知が続いたときは「**3人がリアクションしました**」のように 1 件にまとめます（リアクションは絵文字ごとの内訳も表示）。「個別に表示」で 1 件ずつに戻せます。返信・メンションは 1 件ずつ読む意味があるためまとめません。 |

## 4. 認証とアカウント

| 機能 | 説明 |
| :--- | :--- |
| **登録モード（管理画面で切替）** | **自由登録（`open`）** / **招待制（`invite`・コード必須）** / **承認制（`approval`）** / **新規登録の一時停止（`closed`）** の 4 つ。承認制では、アカウントを作りたい人が ID・表示名などと任意の申請メッセージを送り、**管理者が承認したときだけ**ログインできます（承認まではログイン不可・検索や連合先からも見えません）。却下した場合は理由が申請者のログイン時に表示されます。 |
| **マスターキー認証（既定）** | アカウント登録時に暗号学的に安全なマスターキーを発行し、ユーザー自身がアカウントの完全な所有権を持ちます。平文パスワードを保存しません。 |
| **パスワード方式（管理画面で切替）** | メールアドレス＋パスワードでの登録・ログイン。管理者が「メール・認証」タブで切り替えます。 |
| **パスワードの設定・変更** | `POST /api/user/password`。パスワード設定済みなら現在のパスワードまたはマスターキー、未設定ならマスターキーで設定します。 |
| **登録時のメール確認（SMTP 設定時のみ）** | 6桁の確認コードをメールで送り、一致した場合のみ登録を受け付けます（`email_verified` を立てます）。**SMTP 未設定のサーバーではコードを要求せず、従来どおり登録できます**。 |
| **パスキー（WebAuthn）** | Windows Hello / Touch ID / Face ID / 物理セキュリティキーで、長いキーを入力せずにサインインできます。 |
| **メールアドレス登録と復元** | マスターキーを紛失したとき、メール経由で新しいキーを再発行できます（存在秘匿のため、該当なしでも同じ応答を返します）。 |
| **セッション管理** | 端末ごとのセッション一覧とログアウト。 |
| **フォロワー / フォロー中の一覧** | プロフィールの「フォロー中」「フォロワー」の数字をクリックすると一覧が開きます（ローカル・リモートの混在、アイコンとハンドルつき）。未ログインでも他人のプロフィールから見られます。 |
| **プロフィール項目** | 名前・自己紹介・アイコン・バナーに加えて、リンク集（最大4件）を設定できます（ActivityPub の `attachment` として連合先にも表示）。**ディレクトリ掲載の可否は `discoverable` として Actor 文書にも出る**ので、連合先にも意思が伝わります。 |
| **🧭 初期設定ウィザード** | アカウント作成の直後に、プロフィール（アイコン・名前・自己紹介）→ プライバシー → フォロー → プッシュ通知 → 完了 の順に案内します。「あとで」でいつでも中断でき、設定画面の「初期設定をもう一度行う」から開き直せます（どちらも状態はサーバーに保存されるので、別の端末で開き直しても二度は出ません）。 |
| **🔒 プライバシー設定（検索エンジン・生成AI）** | 「検索エンジンによるインデックスを拒否」と「生成AIによる学習を拒否」を利用者ごとに設定できます。プロフィールの HTML に `<meta name="robots">`（`noindex, nofollow` / `noai, noimageai`）として出し、`noindex` の利用者は sitemap からも外します。**これは意思表示であって、クローラの遵守を強制するものではありません**（サイト全体の `robots.txt` と併用してください）。 |
| **データエクスポート** | 全投稿・フォロー／フォロワー・ブックマーク・リアクション履歴を JSON または ZIP で一括ダウンロード。**ZIP の生成はバックグラウンドで走ります**（受け付けたら `jobId` が返り、進み具合を見てから落とせます。ファイルは 1 回だけ落とせます）。 |
| **アカウント移行インポート** | Mastodon の `outbox.json` / Misskey の `notes.json` に加えて、**Spica 自身のエクスポート（JSON / ZIP）** を取り込みます。投稿（本文・CW・公開範囲・**元の投稿日時**・返信先）に加えて、**メディアの実ファイル（ZIP 内の画像をドライブへ保存して投稿に紐づけ）・フォロー／フォロワー・ブックマーク・リアクション**も復元します（再取り込みでも重複しません。ZIP のパス検証・件数とサイズの上限つきで、超過は打ち切り＋件数報告）。 |
| **引っ越し（Move）** | 引っ越し先で `alsoKnownAs` を設定してから実行すると、フォロワーへ `Move` が配送され、フォローが引き継がれます。受信側でも検証して処理します。 |
| **アカウント削除** | 自分の全データを削除し、連合先へも `Delete` を配送します。ドライブのメディアも台帳・ストレージから消えます。**受け付けた時点でアカウントは凍結され、全セッションが切れます**（削除本体はバックグラウンドで進みます）。 |

## 5. 連合（ActivityPub / Fediverse）

| 機能 | 説明 |
| :--- | :--- |
| **プロトコル対応** | Actor 文書、WebFinger、NodeInfo 2.1、Inbox / Outbox、HTTP Signatures。 |
| **リレー** | 連合リレーへの接続と送受信。転送（代理配送）は既定で「管理画面で承認済みのリレーのみ」許可します（`INBOX_FORWARDED_ACTIVITY_POLICY`）。 |
| **配送リトライ** | 一時的な失敗（ネットワーク・408・429・5xx）は `outbox_deliveries` に積み、指数バックオフ（1分→5分→15分→1時間→3時間→12時間→24時間、最大9回 ≒ 2.5日）で再送します。恒久的な失敗は再送しません。管理画面の「配送キュー」で滞留・失敗の確認と再送ができます。 |
| **配送の宛先をまとめる** | フォロワーの Inbox は**同じサーバーなら sharedInbox 1 つに集約**し、同時実行数を `DELIVERY_CONCURRENCY`（既定 5）までに絞って送ります。フォロワーが増えても 1 投稿あたりの送信数と DNS 解決が膨らみません。 |
| **外向き取得のタイムアウト** | 配送・Actor 文書・WebFinger・リンクプレビュー・画像プロキシの取得は `FEDERATION_TIMEOUT_MS`（既定 15 秒）で必ず打ち切り、リダイレクトは 1 ホップずつ検証します。相手が黒穴でもソケットを掴んだまま戻りません。 |
| **WebFinger のキャッシュ** | `@user@remote` の解決結果を 10 分（失敗は 60 秒）だけ覚えます。検索・フォロー・メンションのたびにネットワークへ出ません。 |
| **受信の受け入れ制御** | 受信の処理（署名検証の後に走る DB 書き込み・アンテナ照合・配信）は同時 `INBOX_CONCURRENCY`（既定 4）件まで、順番待ちは `INBOX_QUEUE_MAX`（既定 200）件まで。溢れたぶんは 503 を返し、送信側の指数バックオフで再送されます（混み具合は `/health` の `inbox`。`INBOX_QUEUE_WAIT_MS=0` は「待たない」＝空きが無ければ即 503）。 |
| **受信の非同期処理（任意）** | `INBOX_ASYNC=true` にすると、署名検証と形式の検査だけリクエスト内で済ませて **202 を返し**、書き込み・アンテナ照合・通知・配送の積み込みはキュー（`jobs`）＋ワーカーが行います。**順序はアクターごとの FIFO**（同じ相手の Create → Delete / Update は入れ替わりません）で、Delete の墓標（`deleted_remote_posts`）があるので「削除の後に届いた Create」が復活させることもありません。滞留は `/health` の `inboxQueue`（`pending` / `running` / `failed`）で見えます。**既定は無効**（1 プロセスで動かすと重い処理は同じスレッドで走るので速くはなりません。別プロセスなら `PROCESS_ROLE=worker`）。 |
| **受信 Block の尊重** | 他サーバーのユーザーから Block を受け取ったら記録し、その相手への配送を抑制します（`Undo Block` で解除）。 |
| **リアクションの取り消し（Undo）** | 他サーバーからの Like / EmojiReact の `Undo` は、**Undo が指す活動 1 件だけ**を消します（受け取った活動の id を `reactions.id` に保存しているため）。活動 id が特定できないときだけ、埋め込みの絵文字 → 投稿 URL、の順に手がかりを落として消します。切り替え（❤️→💯）の直後に届いた Undo が新しいリアクションまで巻き込んで消してしまう事故を防ぎます（取り消しも SSE で即時に配られます）。 |
| **DM（管理者が有効化したときのみ）** | 連合する1対1のメッセージ。受け取りは相手の許可リスト制（既定では誰からも受け取りません）、サーバーへの保存とアプリ内通知のみ（通知本文にメッセージ本文は入らず、メール通知には載りません）、宛先でない人には本文も存在も見えません（タイムライン・検索・RSS・sitemap・OGP・エクスポートにも出ません）。サーバー管理者の設定 `dm_enabled`（既定はオフ）が on のときだけ使え、オフのときは API が 404 になり受信も保存しません。詳細は [README の「DM について」](../README.md#-dm1対1のメッセージについて)。 |
| **Authorized Fetch（任意）** | 有効にすると、こちらの取得（Actor 文書・フォロワー一覧・ノート）にも署名を付け、取得側にも署名を必須にします。フォロワー限定投稿の保護が実効化されます（`AUTHORIZED_FETCH`）。 |
| **通報の連合** | 他サーバーのユーザーを通報すると `Flag` として転送され、他サーバーから届いた通報も取り込みます。 |
| **ピン留め（featured）** | プロフィールのピン留め投稿を `featured` コレクション（`/users/<id>/collections/featured`）として公開し、Actor 文書から参照します。Mastodon / Misskey 側でも「固定投稿」として見えます（公開投稿のみ掲載）。 |
| **アイコンと名前の反映** | 管理画面でサーバー名・説明文・アイコンを変えると、**favicon / apple-touch-icon / PWA の manifest（アプリ名・説明・アイコン）/ 共有カードの画像（og:image）** にそのまま反映されます（`/favicon.ico` も設定したアイコンへ転送）。 |
| **発見性** | RSS（`/feed.xml`、`/users/<id>/feed.xml`、`/tags/<tag>/feed.xml`）、投稿・プロフィール・タグページへの OGP / Twitter Card 動的注入、oEmbed エンドポイント（`/api/oembed`）、`robots.txt` と `sitemap.xml`、`/.well-known/security.txt`（`contact_url` 設定時のみ）。すべての HTML に `canonical`・`meta description` と RSS / oEmbed の自動発見リンクを出します。 |
| **投稿のパーマリンク** | ローカル投稿は `/users/<id>/posts/<postId>` が正規 URL で、**同じ URL がブラウザには OGP 付きの画面、ActivityPub のクライアントには JSON** を返します（Mastodon と同じ挙動）。リモート投稿は `/?post=<正規 ID>` で共有でき、どちらも `canonical` で一本化されます。古い `/posts/<正規 ID>` 形式のリンクは 301 で転送します。 |
| **共有** | 投稿の「共有」は、共有シートが使える端末では OS の共有（`navigator.share`）を開き、無ければ URL をクリップボードへコピーします。ハッシュタグは `/tags/<tag>` へのリンクで、タグページは共有も購読もできます。 |

## 6. セキュリティ

- **署名検証（strict 既定）**: 受信 Activity は鍵の持ち主と `actor` の一致・Digest・署名の鮮度を検証し、失敗は 401 で拒否します。なりすまし・改ざん・リプレイを防ぎます。
- **SSRF 対策**: リモート取得先のプライベート IP・内部ホスト名を拒否します（`ALLOW_PRIVATE_REMOTE_FETCH` でローカル検証時のみ許可）。
- **レート制限**: 認証 20回/分、API 600回/分、Inbox 3000回/分。**認証済みのリクエストは利用者ごと**に数え（`user:<id>`）、未認証だけ IP 単位です（NAT 配下の巻き添えと、IP を替えての素通りを防ぎます。`RATE_LIMIT_DISABLED` で無効化）。
- **プロキシの信頼範囲**: `trust proxy` は既定で `loopback`（127.0.0.1 からの `X-Forwarded-For` だけを信頼）。`TRUST_PROXY` で前段のアドレスや段数を指定できます。誰の `X-Forwarded-For` も信じる設定にすると、IP 判定を詐称できます。
- **トランザクションの隔離**: SQLite では 1 接続を共有しているため、トランザクションが開いている間は**他のリクエストの文を待たせます**（他人の書き込みが `ROLLBACK` に巻き込まれない）。
- **XSS 対策**: 投稿本文などはクライアント側で DOMPurify を通してから描画します。
- **機密情報の分離**: `.env`・SQLite・アップロード類は Git 追跡から除外されています。
- **コミット前の秘密スキャン**: `npm run check:secrets` が秘密鍵・アクセストークン（AWS / GitHub / Slack 等）・`.env`・SQLite・鍵素材の混入を検出します。`npm install` 時に git フック（`.githooks/pre-commit`）が自動で有効になり、検出時はコミットが中止されます（`--no-verify` で回避可）。

## 7. モデレーションと管理

管理パネル（Web UI）から以下を操作できます。

- **ダッシュボード**: ユーザー数・投稿数などの概況
- **ユーザー**: 凍結・削除・ロール（権限）付与
- **連合**: リレーの追加・承認
- **🧾 監査ログ**: 管理パネルからの変更操作（誰が・いつ・何を・どの対象に）を記録し、「監査ログ」タブで読めます。パスワードやトークンは記録時に伏せられます。拒否された操作（403）は記録しません。管理者のみ閲覧でき、180 日より古いものを画面から削除できます。
- **🎭 ロール / 権限**: `admin`（すべての管理操作）と `moderate`（通報対応・凍結・ドメインブロック）の 2 段階。モデレーターも管理パネルに入れますが、表示されるのは通報とブロックだけです（画面の出し分けは `/auth/me` が返す `permissions` で判断します）。最後の管理者を外す操作は拒否されます。
- **ブロック / サイレンス**: ドメイン単位で 2 段階。**🚫 ブロック（suspend）** は通信を 403 で遮断しキャッシュも削除、**🔇 サイレンス（silence）** は通信とフォロー関係を維持したまま、そのサーバーの投稿をホーム・ローカル・検索・通知から隠します（データは消さないので後から戻せます）
- **通報**: 未対応件数つきのキュー。対応済み／却下／再オープン、`Flag` の転送。**通報した本人は「設定 → ミュートとブロック」の「送信した通報」で、自分の通報の対応状況と対応メモを確認できます**（以前は送れるだけで、その後どうなったかが見えませんでした）
- **お知らせ**: 全ユーザーへの一斉告知（タイムライン上部にバナー表示）
- **カスタム絵文字**: サーバー独自絵文字の登録
- **招待コード**: 招待制の運用
- **📝 承認待ちの申請**: 承認制（`approval`）のとき、ユーザータブの先頭に申請の一覧が出ます。ID・表示名・自己紹介・申請メッセージ・連絡先（パスワード方式ならメール）を見て、**承認**か**拒否**（理由つき）を選べます。承認待ちの件数はタブにバッジで出ます
- **サーバールールと同意フロー**: ルール・利用規約・プライバシーポリシーを管理画面から設定でき、新規登録時に同意モーダルを表示します（同意必須の ON/OFF も切替可能）

- **ストレージ / メール・認証 / 配送キュー / 設定**: 外部ストレージ、SMTP、認証方式（マスターキー／パスワード）、登録時のメール確認、サーバールール・規約 URL など

## 8. 1人運用のための機能

| 機能 | 説明 |
| :--- | :--- |
| **DB メンテナンス** | `npm run db:maintenance`。①古いリモート投稿の保持期間削除、②孤立メディアの削除、③FTS セグメントのマージ＋wal_checkpoint＋VACUUM、④`VACUUM INTO` によるバックアップ、⑤保存・索引の方針（設定値）の適用、⑥画像プロキシのキャッシュ整理。既定はドライランで、`--apply` で実行します（PostgreSQL ではこの CLI は使わず、自動メンテナンスと `npm run db:pg:backup` を使います）。詳細は [SETUP_Normal.md](SETUP_Normal.md)。 |
| **毎日の自動整理** | サーバー常駐のまま、既定で毎日 4 時以降に「バックアップ → 方針適用 → 保持期間を超えたリモート投稿の削除 → 画像プロキシの整理 → 期限切れセッション・古い通知の掃除」を実行します（管理画面から ON/OFF・時刻変更・即時実行が可能）。VACUUM だけは手動（サーバー停止時）です。 |
| **自動バックアップ** | 整理の前に `VACUUM INTO` でスナップショットを取り、`server/data/backups/` に既定 3 世代保持します。`db:maintenance --backup-only` で単独実行もできます。 |
| **容量ダッシュボード** | 管理画面のダッシュボードに DB サイズ・WAL・投稿数（ローカル/リモート）・索引行数・ドライブ使用量・画像プロキシのキャッシュ・削除予定件数・バックアップ世代を表示します。 |
| **画像プロキシのキャッシュ管理** | キャッシュは `server/data/proxy-cache/` に置き、既定 512MB・30 日で整理します（`IMAGE_PROXY_MAX_MB` / `IMAGE_PROXY_TTL_DAYS`）。毎日の自動整理と `db:maintenance`（⑥）が期限切れ分と容量超過分を削除します。管理画面から「キャッシュを整理」で即時削除もできます。 |
| **ヘルスチェック** | `GET /health`（`/api/health` も同様）が DB 応答を確認して 200 / 503 を返します。セッションを付けると詳細（DB サイズ・投稿数・配送キューの滞留 `pending`/`delivering`・ジョブキュー・自動整理・バックアップ・Redis・SSE 接続数・タイムラインキャッシュ）も返します（Authorized Fetch 有効時も署名不要）。 |
| **転送量の削減** | 応答は gzip で圧縮して返します（SSE は対象外。1KB 未満は圧縮しません）。ビルド済みの静的ファイルは内容が変わらないもの（`assets/` の下）に 1 年キャッシュを付け、`index.html` や `sw.js` は毎回確認させます。クライアントの JS は 859KB → 202KB（gzip 実測）になります。nginx の設定例にも `gzip` を入れてあります。 |
| **計測（PostgreSQL）** | `npm run db:pg:stats` で、実行時間の合計が大きいクエリ・1 回あたりが遅いクエリ・テーブルと索引のサイズ・使われていない索引・長く開いているトランザクションを表示します（クエリ統計には `pg_stat_statements` が必要。無い場合は有効化の案内を出します）。 |
| **ジョブキュー（背景処理）** | DB の `jobs` テーブルに積んで、ワーカーが実行します。指数バックオフつきの再試行、処理中に落ちた行の復帰、同じ仕事を二重に積まない `dedupeKey`、`/health` での件数表示。いまはリンクプレビューの取得が載っています（即時取得を試みて、失敗したらキューが再試行）。複数プロセスでも 1 つだけが実行します（条件付き UPDATE。Redis も専用ミドルウェアも不要）。 |
| **配送の並列化** | 配送は 1 件ずつ「自分が送る」と宣言してから送るので、二重送信にならずに並列化できます（`DELIVERY_CONCURRENCY`、既定 5）。複数プロセスでも同じ仕組みで動きます。 |
| **タイムラインの読み取りキャッシュ** | `TIMELINE_CACHE_TTL_SEC`（**既定 15 秒**。`0` で無効）で、同じ画面を何度も開いたときの組み立てを省きます（組み立てはカウンタ 3 本 → 1 本・閲覧者の状態 4 本 → 1 本に統合し、独立な取得は並行に流します）。Redis があれば全プロセスで共有、無ければプロセス内。**投稿・削除・ブースト・フォロー・ブロック・ミュートワード・ドメイン遮断、および連合からの受信の直後は捨てる**ので、新しい投稿はすぐ見えます（リアクション・ブックマーク・投票だけは TTL ぶん古く見え得ます。利用者ごとに分かれているので漏れはしません）。`/health` と `/metrics` の `timelineCache` でヒット率が見えます。 |
| **グレースフルシャットダウン** | `SIGTERM` / `SIGINT` で SSE を閉じ、WAL をチェックポイントしてから終了します（POSIX 環境）。 |
| **検索索引・ブーストの方針** | 管理画面 → サーバー設定 →「検索とリモート投稿の保存」で変更できます（`FTS_INDEX_SCOPE` / `REMOTE_ANNOUNCE_POLICY`）。既存データへは `db:maintenance -- --apply` で遡及適用します。 |
| **リモート投稿の保持期間** | `REMOTE_POST_RETENTION_DAYS`（既定 30 日）。ブックマーク・ピン留め・ローカル投稿の返信先/引用元・ローカルのリアクション/ブースト・ローカル投稿への返信・フォロー中アクターの投稿は残します。 |
| **バックアップ** | `db:maintenance` が削除前に `VACUUM INTO` でスナップショットを作成し、`server/data/backups/` に世代管理（既定3世代）します。 |
| **複数人での運営** | 管理者を複数置けます（ロールで `admin` / `moderate` を付与）。監査ログで操作の履歴が残り、通報は運営全員に通知されるため、担当を決めて交代で見られます。DM は既定オフで運営同士の連絡には使えません（有効化してもサーバーに保存され、運営者は DB を読める立場にあるためです）。**機微な連絡はノード外の手段で**行ってください。 |
| **PostgreSQL 対応（任意）** | 既定は SQLite で、`DB_DRIVER=postgres DATABASE_URL=...` を設定したときだけ PostgreSQL で動きます（既定は SQLite のまま）。データ層は非同期で、どちらのドライバも同じコードで動きます。接続はコネクションプール（`DATABASE_POOL_MAX`）、接続断はプールが張り直します。設計・移行手順・制約は [POSTGRESQL.md](POSTGRESQL.md)、SQL 翻訳の検証は `npm run test:pg-translate`、非同期層の検証は `npm run test:db-async`、PG の全スイートは `bash scripts/run-suites-pg.sh`。 |
| **Redis 対応（任意）** | `REDIS_URL` を設定したときだけ有効になります（未設定なら今までどおりインメモリ＝1 プロセス前提）。レート制限のカウンタ・リアルタイム更新（SSE）の Pub/Sub・設定変更の通知・定期処理の単一実行ロックを全プロセスで共有し、複数プロセスで動かせるようになります。落ちてもノードは止まりません（インメモリに戻ります）。手順は [REDIS.md](REDIS.md)。 |
| **検証スクリプト** | 連合・署名検証・配送・ページネーション・ドライブ・通知設定・動画サムネイルなど、`npm run test:*` で機能ごとの検証を実行できます。 |

## 9. サードパーティ製クライアント（Misskey 互換 API）

**Misskey 互換の API を実装しています。** Misskey 系のクライアント（SubwayTooter、Miria など）から、
ログインして読み書きできます（`scripts/test-misskey.ts` で検証。SQLite / PostgreSQL の両方で回します）。

| 機能 | 説明 |
| :--- | :--- |
| **ログイン（MiAuth）** | Misskey 標準の MiAuth に対応。クライアントがブラウザで `https://<ホスト>/miauth/<session>` を開くと承認画面が出て、許可するとトークンが渡ります。**要求された権限は画面に表示します**が、Spica はアプリごとに権限を分けていないので、承認するとアカウントでできること全部を許可します（不要になったら「設定 → セッション・ログアウト」で切れます）。本文の `i` でもトークンを渡せます。 |
| **読み取り** | ホーム / ローカル / 連合タイムライン、ノート単体、会話（親 + 返信）、ユーザー情報・ユーザーのノート、フォロワー / フォロー中、通知、ハッシュタグのトレンド、ノート検索。`untilId` / `sinceId` でのページングに対応します。 |
| **書き込み** | 投稿（本文・CW・公開範囲・返信・引用・ブースト・アンケート・メディア添付）、削除、リアクション、お気に入り（ブックマーク）、フォロー / 解除、アンケート投票、ドライブへのアップロード。 |
| **ID の扱い** | Misskey のクライアントは ID を**文字列として並べると時刻順**になる前提でページングします。Spica の投稿 ID は URI なので、外には `<時刻(base36)><ハッシュ>` という Misskey 風の ID を出し、受け取ったときは時刻の前後を索引で引いて照合します（テーブルは増やしていません）。 |

**未対応（方針・制限）**:

- **ストリーミング（WebSocket）**: **対応しました**（`wss://<host>/streaming?i=<トークン>`）。`localTimeline` / `globalTimeline` / `homeTimeline` / `hybridTimeline` / `main`（自分の通知）を購読でき、ノートと通知が Misskey の形式で流れます。匿名接続は公開タイムラインのみ、30 秒間隔の ping で無通信の接続は閉じます。Spica 自身の画面は従来どおり SSE です。
- **`visibility: specified`（DM）**: **送信は `/api/dm/messages` から**行います（DM が有効なときだけ）。受信は DM が有効なときだけ受け付けます（無効のときは保存せず 202 を返します）。詳細は [README の「DM について」](../README.md#-dm1対1のメッセージについて) を参照してください。
- **権限の細分化**: 上に書いたとおり、MiAuth の権限は表示だけで、トークンはアカウント相当です。
- **Mastodon 互換 `/api/v1/*`**: 未実装です（Spica 独自の REST API と Misskey 互換 API を使います）。
