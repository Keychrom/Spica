# Spica と他の Fediverse ソフトの比較（2026-10 時点）

Spica を Misskey / Mastodon / Akkoma / Iceshrimp.NET と並べて、
**仕様の違い**と**設計の哲学**をまとめたものです。

「どれが上か」ではなく、**同じ ActivityPub でも育った文化が違う**ことを見るための資料として書いています。
バージョンによって変わる部分があるので、細かい数字は各ソフトの最新のドキュメントも見てください。

## 1. ひと目で分かる比較表

| :--- | :--- | :--- | :--- | :--- | :--- |

## 3. 哲学（何を大事にしているか）

### Mastodon — 「安全で、誰でも使える大きな広場」
- もっとも「製品」として作られている。**初心者が迷わないこと**と**安全**を優先する。
- 検索を弱くし（他人の投稿を勝手に掘らせない）、引用にも相手の許可を挟む（4.4 以降）。
- CW とフィルタの文化。1投稿 500 字。リアクションは ☆ だけ（**感情の表現は「お気に入り」1つ**に絞る）。
- 大きなインスタンスを運用する前提の道具立て（モデレーション、ドメインブロック、OAuth アプリ登録）。

### Misskey — 「表現と遊びのための道具箱」
- リアクション・MFM・Drive・アンテナ・クリップ・デッキ UI…と**同じ横並びでも機能が多い**。
- サーバーごとの文化（テーマ、カスタム絵文字）を大事にする。**管理者の色が出る**。
- API が広く公開され、サードパーティ製クライアントが育った（=サーバーが UI を独占しない）。
- そのぶん運用は重め（PostgreSQL + Redis、機能が多くデータも増える）。

### Akkoma — 「軽くて、自由で、開発者のためのサーバー」
- Pleroma の思想を継ぐ: **少ない資源で大量に捌く**。Elixir で 1 コアでも軽い。
- MRF（メッセージ書き換え）でサーバーごとに連合のルールを細かく決められる。**小規模コミュニティ向け**。
- 機能の網羅性より「自分たちで決められること」を重んじる。UI は素朴になりがち。

### Iceshrimp.NET — 「モダンな土台で、両方の文化に橋をかける」
- Iceshrimp（Misskey 系）を **C#/.NET で書き直した**もの。性能と保守性の作り直しが目的。
- 構成は **PostgreSQL だけで足りる**（Redis などの追加ミドルウェアを要求しない）。
- **Misskey 系と Mastodon 系の両方の API を話せる**ので、どちらのクライアントからも使える。
- レガシーを引きずらない設計（新しいサーバーほど「実装の素直さ」を優先）。

### Spica — 「小さく始めて、自分で全部を持てる」
- **SQLite 既定・Redis 無しでも動く**。1人が 1 台で運用することを前提に、機能を足すより
  **壊れない・速い・軽い**ほうを選ぶ（読み取りは計測して直す、遅いクエリは形から直す）。
- **PWA が公式クライアント**。ネイティブアプリを持たない代わりに、インストール・通知・
  共有シート・アイコンバッジまで面倒を見る（「アプリを配る」より「ブラウザを良くする」）。
- **1対1の DM は既定でオフ**（2026-10-07 に方針変更。以前は電気通信事業法の扱いを避けて
  実装しないことにしていました）。管理者が有効化したときだけ使え、受け取りは相手の許可リスト制、
  保存とアプリ内通知のみ（メール通知には載せない）。詳細は
  [README の「DM について」](../README.md#-dm1対1のメッセージについて)。
- 連絡は基本はメンション・公開の場で、という姿勢は変わらない。
- 連合は**受け取る側の作法を守る**: 署名検証は既定で厳格、Authorized Fetch にも対応、
  相手が署名を要求してきたらこちらも署名して取りに行く（iceshrimp.NET のように
  未署名の取得を 401 で断るサーバーとも繋がる）。
- 拡張（プラグイン）は**意図的に無し**。設定でできることを増やし、挙動は読めば分かるように保つ。

## 4. 相互運用で実際に起きること

同じ ActivityPub でも、**文化の差がそのまま見え方の差**になります。

| 起きること | なぜ |
| :--- | :--- |
| Spica の 👍 が Mastodon では ☆ にしか見えない | Mastodon には絵文字リアクションの概念が無い（Like 1 種類） |
| Mastodon の ☆ が Spica では ❤️ として届く | Spica は `Like` を ❤️ のリアクションとして扱う |
| リアクションの**取り消し**が他ソフトで効かないことがある | 取り消しは `Undo` の形が実装ごとに違う（活動の id を送る / 埋め込む / 投稿 URL を送る）。Spica は 3 形式すべてを受ける |
| 引用が Mastodon では「ただのリンク付き投稿」になることがある | Mastodon の引用は相手の許可が要る・バージョン依存 |
| 長い投稿が Misskey / Mastodon で切れて見える | 文字数の上限がサーバーごとに違う（表示側の制限） |
| CW の扱いがずれる | CW の文化が強いのは Misskey / Mastodon。Akkoma / Iceshrimp は素直に通す |
| 未署名の取得を断るサーバーがある | Authorized Fetch（署名を要求する設定）。Spica は 401/403 のとき署名付きで取り直す |
| 相手が「新しい端末からログイン」を通知してくれない | 通知の種類がソフトごとに違う |

## 5. まとめ（選び方の目安）

- **人が多く集まる場所にいたい** → Mastodon（文化・ツール・アプリが揃っている）
- **表現と遊びを広く使いたい** → Misskey（機能とカスタマイズの量）
- **小さく軽く、自分で決めたい** → Akkoma（省資源 + 連合のルールを自分で書ける）
- **モダンな実装で、両方のクライアントを使いたい** → Iceshrimp.NET
- **1 台で静かに始めて、必要な機能だけを確実に動かしたい** → Spica

連合している以上、どれを選んでも**同じネットワークの住人**です。
違うソフトどうしが同じ投稿を別の顔で見せる、そのズレ込みで面白いところだと思っています。
