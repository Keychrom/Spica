# 🔐 2段階認証（TOTP） (SECURITY-2FA.md)

パスワードやマスターキーが漏れても、それだけではログインできないようにする任意の仕組みです。
**既定は無効**で、使いたい人が設定画面から自分で有効にします（サーバー側で強制はしません）。

## 1. 何を使うか

RFC 6238 の TOTP（Time-based One-Time Password）です。Google Authenticator / Microsoft Authenticator /
1Password / bitwarden など、**`otpauth://` の QR コードを読めるアプリ**ならどれでも使えます。

- アルゴリズム: HMAC-SHA1・6桁・**30 秒**ステップ（相互運用のため最も一般的な組み合わせ）
- 時計のずれを考慮して、**前後 1 ステップ（±30 秒）** まで受け付けます（合計 90 秒の猶予）
- サーバーとアプリの時計が大きくずれていると通らないので、端末の時刻は自動合わせにしてください

## 2. 有効にする流れ

設定画面 →「セキュリティ」→「2段階認証」から有効にします。

1. `POST /api/me/totp/setup` … 新しい秘密（base32）を発行し、`otpauth://totp/...` の URI と一緒に返します。
   この時点では**まだ有効になりません**（`totp_enabled = 0` のまま）。
2. アプリで QR コードを読み取り、表示された 6 桁を `POST /api/me/totp/enable` に送ります。
   サーバーが検証して一致したときだけ有効化し、**リカバリーコード 10 個**を返します。
3. 返ってきたリカバリーコードを必ず保管してください。**この 1 回しか表示されません**。

途中でやめた場合も、確定するまでは有効にならないのでログインは今までどおりです
（再び `setup` を呼ぶと秘密は上書きされます）。

## 3. ログインの流れ

有効にすると、ログイン時にマスターキー（またはパスワード）だけでは入れなくなります。

- コード無しでログインを試すと `401` と `{ "totp_required": true }` が返ります。
- クライアントは 6 桁の入力欄を出し、`totpCode` を付けて**もう一度**ログインします。
- コードが正しい（またはリカバリーコードが有効）ときだけセッションが発行されます。

`totpCode` の欄には**リカバリーコードもそのまま入力できます**（下記）。

退会（`POST /api/user/delete-me`）でも同じです。マスターキーまたはパスワードに加えて、2段階認証が
有効なアカウントでは `totpCode`（リカバリーコード可）が必要になります。資格情報だけでは退会できません。

パスキー（WebAuthn）でログインする場合も同じです。パスキーは「持っているもの」1 要素として数え、
2段階認証が有効なアカウントでは**コードの入力が必須**になります。

1. `/api/webauthn/authenticate/options` が `totp_required` を返します（`user_id` を付けたときだけ分かる情報です）。
2. 生体認証（`/api/webauthn/authenticate/verify`）が通り、コードが無い（または誤っている）ときは
   `401` と `totp_required: true`・`pendingToken` が返ります。
3. パスキーをやり直さずに `POST /api/webauthn/authenticate/totp` へ `{ pendingToken, totpCode }` を送ります
   （`totpCode` にはリカバリーコードもそのまま使えます）。コードが誤っていても `pendingToken` は**失効しません**。
4. コードが正しければセッションが発行されます。`pendingToken` はその場で消費され、二度は使えません。

`pendingToken` は**パスキーの検証が通ったあとにしか発行されない**（これだけではログインできない）・
5 分で失効する・1 回だけ使える一時トークンです。以前はここで認証チャレンジを消費していたため、
コードを入れ直しても「チャレンジが無効」で必ず失敗していました（2026-10-16 に修正）。

> いまの標準クライアント（`client/`）にあるのは**パスキーの登録・削除**（設定 →「セキュリティ」）で、
> **パスキーでログインする入口はまだありません**。上の流れは API としての仕様で、パスキーログインを使う
> クライアント（Misskey 互換クライアントや将来の追加分）から利用できます。ログインは
> マスターキー、またはメール＋パスワード＋（有効なら）コードで行えます。

## 4. リカバリーコード

端末を無くした・アプリを消したときのための**1 回限りの合言葉**です。

- 形式は `XXXXX-XXXXX` の 10 個。**サーバーには SHA-256 のハッシュだけ**を保存します（平文は保存しません）。
- 使うと**その 1 個だけ**が消え、残りは使えます。使い回しはできません。
- 設定画面に残りの個数が出ます。減ってきたら `POST /api/me/totp/recovery-codes`（コード入力が必要）で
  再発行でき、**古いコードは全部無効になります**。

## 5. 無効にする

`POST /api/me/totp/disable` に現在のコード（またはリカバリーコード）を付けて呼びます。
無効にすると秘密もリカバリーコードも削除されます（`totp_secret = ''`、`totp_recovery_codes = '[]'`）。

**コードを失って、リカバリーコードも無い場合**は、そのアカウントでは二度とログインできません。
サーバー管理者でも解除できません（DB を直接書き換える以外に方法がありません）。
だからこそ、有効化した直後にリカバリーコードを保管してもらうのが前提の設計です。

## 6. 保存と実装

| 場所 | 内容 |
| :--- | :--- |
| `users.totp_secret` | base32 の秘密。有効・無効にかかわらず設定中の秘密を保持します |
| `users.totp_enabled` | `1` のときログインでコードを要求します（既定 `0`） |
| `users.totp_recovery_codes` | リカバリーコードの SHA-256 ハッシュの JSON 配列（既定 `[]`） |

実装は `server/src/totp.ts`（アルゴリズム本体。RFC 6238 のテストベクタで検証しています）と
`server/src/totpService.ts`（保存まわり）、API は `/api/me/totp*` です。
`/auth/me` が `totp_enabled` を返すので、クライアントは設定画面の状態表示に使えます。

チャレンジ（`webauthn_challenges`）は発行時に**どの利用者のものか**を記録し、消費するときに
「そのチャレンジの持ち主」と「クレデンシャルの持ち主」が一致することを確かめます
（一致しなければ拒否するので、他人のチャレンジを自分に使い回すことはできません）。
`/api/webauthn/authenticate/*` は**認証系と同じ 20 回/分（IP 単位）**に制限しています
（パスキーを持っている相手でも、6 桁のコードを総当たりされないようにするため）。

### パスキーとオリジンの束縛

パスキーは「どのサイトのものか」に束縛されます。Spica は検証に使う `origin` と `rpID` を
**既定では設定（`PROTOCOL` + `DOMAIN`）から作り**、リクエストが名乗った `Origin` ヘッダーは流用しません
（以前は流用していて、任意のオリジンからパスキーを作れる＝束縛が無効な状態でした。2026-10-16 に修正）。
`rpID` はポートを含まないホスト名です（`DOMAIN=example.com:3000` なら `example.com`）。

リクエストに `Origin` が付いていて設定と違う場合は、`403` でその場で拒否します。開発サーバーなど
**設定とは別のオリジンから開いて確認したい**ときは `WEBAUTHN_EXTRA_ORIGINS`（カンマ区切り）に追加してください。
そこに載せたオリジンだけは**管理者が明示したもの**として扱い、`origin` / `rpID` もそのオリジンに合わせます
（ブラウザはページのオリジンでしか手続きをしないので、合わせないと登録・ログインが成立しません）。

## 7. 運用上の注意

- **サーバー管理者はコードを解除できません。** これは意図した設計です（管理者が他人の 2 段階認証を
  外せると、管理アカウントが乗っ取られたときに意味が無くなります）。運用でユーザーを救う必要がある場合は、
  DB の `users.totp_enabled` / `totp_secret` を直接初期化してください。
- メールによる復元（マスターキーの再発行）は**2段階認証を迂回しません**。新しいマスターキーを得ても、
  ログインにはコードが必要です。
- パスキー（WebAuthn）を使っている場合も、2段階認証を有効にすると**コードの入力が必要**です
  （パスキーは「持っているもの」1 要素として扱います）。
- `/auth/me` や API の応答に秘密は含まれません。`totp_secret` は `setup` の応答でのみ返します。
